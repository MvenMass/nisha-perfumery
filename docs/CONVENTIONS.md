# Правила проекта

Соглашения, по которым написан код «Ниши». Комментарии в коде ссылаются на них вида «(CONVENTIONS.md, правило 4)».

## О проекте
Собственный независимый парфюмерный дом «Ниша» (не мультибренд). Ароматы — «образцы породы»:
у каждого номер образца, материал (известняк, травертин, базальт, орех, янтарь), происхождение,
плотность, пирамида нот (верх / сердце / база). Варианты товара — объёмы (например, 30 / 50 / 100 мл)
со своей ценой и остатком.

## Стек
- Frontend (apps/web): React 19, TypeScript, Vite, React Router, TanStack Query, Zustand, CSS Modules, GSAP + ScrollTrigger.
- Backend (apps/api): Node.js, Fastify, PostgreSQL, Drizzle ORM, Zod.
- Общие контракты (packages/contracts): Zod-схемы и типы, которые используют и web, и api.
- Качество: Vitest, Playwright, ESLint, Prettier, Docker, GitHub Actions. Пакетный менеджер — pnpm workspaces.

## Структура
apps/web/src: app, pages, widgets, features, entities, shared (упрощённый FSD; импорты только «сверху вниз»).
apps/api/src: modules (по доменам: products, auth, cart, orders, admin…), plugins, database, config, shared.
Структура расширяется вместе с функциональностью: без пустых папок и файлов «на будущее».

## Дизайн
- Источник правды — HTML-макеты в docs/design/ (открываются в браузере, в них можно смотреть точные значения):
  home.html (главная, десктоп), home-mobile.html (главная, 360 px), catalog.html (каталог),
  catalog-filters-mobile.html (мобильная панель фильтров), product.html (товар), cart.html (корзина),
  checkout.html (оформление), account.html (личный кабинет, заказы).
  Для страниц без мобильного макета адаптив выводится по образцу home-mobile.html и catalog-filters-mobile.html.
  Плейсхолдеры в квадратных скобках ([ЦЕНА], [АДРЕС БУТИКА]) — данные из БД или конфига, не текст.
  Подписи «[Фото] …» описывают снимок: он верстается как изображение с этим описанием в alt.
- Новые цвета, шрифты и отступы не придумываются: только токены из shared/styles/tokens.css.

## Объём функциональности
- Есть: каталог с фильтрами, товар с вариантами объёма, избранное, корзина, оформление с сохранёнными адресами,
  мок-оплата, личный кабинет с историей заказов, «Повторить заказ», «Сообщить о поступлении» для товара без остатка, админка.
- Нет: промокоды и скидки, платная подарочная упаковка как опция заказа (ручная упаковка — просто преимущество в текстах).

## Обязательные требования к вёрстке
- Mobile-first, адаптив с первой вёрстки (не «потом»). Брейкпоинты: 360, 768, 1024, 1440.
- Поддержка Safari 14.1+ / iOS 14.5+ с самого начала: browserslist и build.target = safari14.
  Без фолбэка не используются: :has(), container queries, dvh/svh, CSS nesting без сборщика, aspect-ratio без фолбэка, structuredClone, Array.prototype.at.
- Типографика русского текста: неразрывные пробелы после предлогов, союзов и коротких слов, перед тире; неразрывный дефис (U+2011) в коротких составных словах.
  Для статичных текстов — прямо в JSX/константах; для текста из БД — утилита shared/lib/typograph.ts.
- Доступность: семантичные теги, настоящие button/a/label, видимый focus, alt у изображений, aria-label у иконок-кнопок, контраст ≥ 4.5:1, зоны нажатия ≥ 44px, prefers-reduced-motion.
- Состояния для каждого экрана: загрузка (скелетоны), пусто, ошибка, 404.

## Правила кода
1. Не создавать абстракции до появления реальной необходимости.
2. Компонент больше ~200 строк — сигнал разделить его по смыслу; но не выносить каждую мелочь в отдельный компонент.
3. Никакого any. Типы данных выводятся из Zod-схем в packages/contracts.
4. Бизнес-логика живёт в одном месте. Цены, скидки, итоги корзины и заказа считает только сервер; клиентской цене не доверять.
5. Деньги — целые числа в копейках. Никакого float.
6. Комментарии объясняют «почему», а не пересказывают код.
7. Никаких пустых catch и проглоченных ошибок. На API — единый обработчик ошибок с понятными кодами.
8. Валидация на клиенте (UX) и обязательно на сервере (безопасность) одними и теми же схемами из contracts.
9. Тесты на важную бизнес-логику (расчёт заказа, остатки, права доступа, слияние корзин).
10. Задача считается выполненной, только когда код реально запущен и проверен: pnpm lint, pnpm typecheck, pnpm test проходят, затронутые сценарии проверены вручную или e2e.

## Безопасность
- Сессии: httpOnly + Secure + SameSite=Lax cookie, таблица sessions в БД, ротация при логине.
- Пароли — argon2. Rate limit на логин и регистрацию. CSRF-защита для изменяющих запросов.
- Роли user / admin, проверка прав на сервере для каждого защищённого маршрута.
- Секреты только в .env (в репозитории — .env.example). Helmet-заголовки, CORS только для своего origin.

## Процесс
- Работа идёт этапами (docs/ROADMAP.md); каждый этап начинается с плана.
- Небольшие осмысленные коммиты в формате Conventional Commits (feat:, fix:, chore:, refactor:, test:, docs:).
- В конце этапа обновляются docs/ROADMAP.md (сделано, отложено, известные проблемы) и docs/DECISIONS.md.
- Команды: pnpm dev, pnpm lint, pnpm typecheck, pnpm test, pnpm test:e2e, pnpm db:migrate, pnpm db:seed.
