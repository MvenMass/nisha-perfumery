- `pnpm lint`, `pnpm typecheck`, `pnpm test` проходят локально и в CI.
- Затронутые сценарии проверены вручную или e2e на 360 / 768 / 1024 / 1440.
- Вёрстка не ломается в Safari 14.1 / iOS 14.5 (нет запрещённых без фолбэка возможностей из CONVENTIONS.md).

- Цвета, шрифты, отступы — только из `shared/styles/tokens.css`; отступления от макетов — только из D-023.
- Русская типографика: неразрывные пробелы и дефисы в статике, `typograph.ts` для текста из БД.
- Коммиты маленькие, Conventional Commits.

## Этап 1. Инициализация monorepo и инфраструктуры ✅

**Цель:** пустой, но рабочий каркас: оба приложения запускаются одной командой, качество проверяется автоматически.

**Задачи**
- pnpm workspaces: `apps/web`, `apps/api`, `packages/contracts`; общий `tsconfig.base.json` (strict, `noUncheckedIndexedAccess`).
- Версии рантайма зафиксированы (`engines`, `.nvmrc`, `packageManager`).
- ESLint (flat config, запрет `any`, правило направления импортов FSD, запрет `structuredClone` / `.at()`) + Prettier, `.editorconfig`.
- `apps/web`: Vite + React 19 + TS, React Router, TanStack Query; `browserslist` и `build.target = safari14`.
- `apps/api`: Fastify, конфиг из env с валидацией Zod, единый обработчик ошибок, `GET /api/health`, Helmet, CORS для своего origin.
- `packages/contracts`: сборка/экспорт, первая схема (ответ health + формат ошибки).
- Docker: `docker-compose` для разработки (PostgreSQL, Mailpit), Dockerfile для api и web.
- `.env.example`, `.gitignore`.
- Vitest во всех пакетах, Playwright с одним smoke-тестом.
- GitHub Actions: install → lint → typecheck → test → build → e2e.
- Корневые скрипты: `dev`, `lint`, `typecheck`, `test`, `test:e2e`. `db:migrate` и `db:seed` появляются в этапе 3 — заглушек «на будущее» не создаём.

**Критерии готовности**
- `pnpm i && pnpm dev` поднимает web и api; страница web получает ответ от `/api/health` через прокси Vite.
- CI зелёный на PR.
- Production-сборка web не содержит синтаксиса новее Safari 14 (проверено по бандлу).
- Секретов в репозитории нет, есть `.env.example`.

## Этап 3. Схема БД, миграции, сиды и контракты ✅

**Цель:** модель данных для этапов 4–7, миграции, идемпотентный сид и Zod-контракты API.

**Задачи**
- Drizzle-схема и миграции (PostgreSQL 18, PK `uuidv7()`):
  - пользователи: `users` (роль, `password_hash` NULL — гостевой аккаунт, D-022), `sessions`, `password_tokens`, `addresses`;
  - каталог: `collections`, `materials` (`swatch_color`), `categories` + `product_categories`, `products` (номер образца, коллекция, материал, происхождение, плотность, концентрация, стойкость, длительности слоёв пирамиды, флаги бестселлер / новинка / срез на главной, публикация, популярность), `product_variants`, `product_images`, `fragrance_notes` + `product_notes` (уровень top / heart / base);
  - покупатель: `favorites`, `carts`, `cart_items`, `stock_notifications` (на товар — D-029);
  - заказы: `orders` (статус и `payment_status`, контакты, способ доставки, снимок адреса, суммы, ключ идемпотентности, срок оплаты), `order_items` (снимок), `order_status_history`, `payments`;
  - `store_settings` — порог бесплатной доставки, цены и сроки доставки, порог «Осталось N», адрес и часы бутика;
  - контентные таблицы (журнал, заявки на консультацию, слайды первого экрана) — миграцией этапа 8.
- Внешние ключи с осознанным `ON DELETE`; CHECK: `price_kopecks > 0`, `stock >= 0`, `quantity > 0`, итог заказа = товары + доставка; уникальные индексы (slug, sku, email, избранное, один активный запрос «Сообщить» на товар и email); индексы под фильтры каталога.
- Enum статусов заказа: pending, paid, shipped, ready_for_pickup, delivered, cancelled (D-043).
- Контракты в `packages/contracts`: каталог, товар, авторизация, корзина, заказ, адрес, общие типы и коды ошибок.
- Сид: материалы, категории, коллекция «Порода», ароматы № 01–12 из макетов (недостающие придумываем), товары «Для дома» и наборы; варианты 30 / 50 / 100 мл, ноты по уровням, категории; администратор из env.
- Скрипты `pnpm db:generate`, `pnpm db:migrate`, `pnpm db:seed`.

**Критерии готовности**
- Миграции применяются на чистую БД (тест и CI); миграции не редактируются задним числом.
- Тесты: constraints реально отклоняют неверные данные, `ON DELETE` ведёт себя как задумано.
- `db:seed` можно запускать повторно без дублей.
- Типы api и web выводятся из схем contracts, `any` нет.

## Этап 4. Срез «Главная, каталог и товар» ✅

**Цель:** пользователь находит аромат через главную, каталог, поиск или подбор и смотрит карточку товара с вариантами объёма.

**Задачи**
- API: `GET /products` — фильтры (категория, материал, коллекция, объём, диапазон цены), сортировка (популярность, цена, новизна), пагинация, только опубликованные; `GET /products/:slug` — варианты, ноты по уровням, изображения; `GET /catalog/filters` — доступные значения фильтров; «Из той же породы» (D-026); поиск.
- «от [ЦЕНА]» — минимальная цена среди объёмов; фильтры объёма и цены применяются к одному варианту (D-025).
- `POST /stock-notifications` — подписка на товар (D-029): email, у вошедшего подставляется; защита от дублей и rate limit. Письма при пополнении — этап 8.
- Главная по home.html и home-mobile.html: «Образцы» и «Срез аромата» — из API, статичные тексты — в коде; первый экран-карусель из 3 слайдов; свет-лампа — простым CSS/JS (полировка — этап 9).
- Каталог по catalog.html и catalog-filters-mobile.html: фильтры и сортировка синхронизированы с URL query, активные фильтры чипами со сбросом, мобильные фильтры в Sheet с кнопкой «Показать N образцов», «Показать ещё» с прогрессом.
- Кнопка «+» в карточке открывает выбор объёма (D-025).
- Товар по product.html: галерея, выбор объёма (цена и наличие меняются, мало остатка — отдельная подсказка), этикетка образца, пирамида нот как срез породы, «Из той же породы», кнопки «в корзину» и «в избранное» (логика — этап 6).
- Поиск (оверлей из шапки) и «Подбор аромата» (D-027).
- Скелетоны, пустой результат фильтров, ошибка, 404 товара; title и description на страницах.

**Критерии готовности**
- Тесты: api — фильтры, сортировка и пагинация, подписка (дубли, rate limit); web — хуки и утилиты фильтрации.
- e2e: фильтр → URL → перезагрузка сохраняет фильтры; «назад» работает; смена объёма меняет цену и остаток.
- Вёрстка совпадает с home / home-mobile / catalog / catalog-filters-mobile / product на своих ширинах; тексты из БД — через `typograph.ts`.

## Этап 5. Срез «Авторизация и роли» ✅

**Цель:** регистрация, вход и выход; сервер различает гостя, пользователя и администратора.

**Задачи**
- API: `POST /auth/register`, `/auth/login`, `/auth/logout`, `GET /auth/me`; argon2id.
- Сессии в таблице `sessions`, cookie httpOnly + Secure + SameSite=Lax, ротация id при входе, срок жизни и продление.
- Rate limit на вход и регистрацию; CSRF-защита изменяющих запросов (D-006).
- Хуки `requireAuth` и `requireRole('admin')`.
- Гостевые аккаунты (D-022): установка пароля по ссылке из письма.
- Web: страницы входа и регистрации (валидация теми же Zod-схемами), пользователь через TanStack Query (`/auth/me`), защищённые маршруты с редиректом и возвратом на исходную страницу.

**Критерии готовности**
- Тесты: регистрация с занятым email, неверный пароль, admin-маршрут обычным пользователем → 403, истёкшая сессия → 401, ротация сессии, rate limit, отказ без CSRF-токена.
- Пароль и хеш нигде не логируются и не уходят в ответах.

## Этап 6. Срез «Избранное и корзина» ✅

**Цель:** пользователь собирает корзину и список избранного; итоги считает сервер.

**Задачи**
- Избранное: у гостя — localStorage, у пользователя — сервер; слияние при входе; страница избранного (D-040).
- Корзина: гостевая — Zustand + persist (localStorage, только `variantId` и количество), серверная — для пользователя; слияние при входе, правило конфликтов — в DECISIONS (D-015).
- API: `GET /cart`, `PUT /cart/items`, `DELETE /cart/items/:variantId`, `POST /cart/merge`; итоги считает сервер по актуальным ценам; снятые и закончившиеся позиции помечаются (D-028).
- UI по cart.html: счётчик в шапке, страница корзины, изменение количества с оптимистичным обновлением и откатом при ошибке; закончившаяся позиция остаётся с пометкой, не входит в сумму и предлагает «Сообщить о поступлении»; пустая корзина — EmptyState.

**Критерии готовности**
- Тесты: расчёт итогов, слияние корзин и избранного, превышение остатка.
- e2e: товар → корзина → изменение количества → итог совпадает с серверным.

## Этап 7. Срез «Заказ, оплата, личный кабинет» ✅

**Цель:** пользователь — зарегистрированный или гость — оформляет и «оплачивает» заказ и видит его в истории.

**Задачи**
- Оформление по checkout.html на одной динамической странице (D-030): контакты, доставка, оплата; курьер / пункт выдачи СДЭК (мок, D-031) / самовывоз из бутика; стоимость доставки считает сервер; адрес — сохранённый или новый с сохранением; гостевое оформление (D-022).
- `POST /orders` в одной транзакции: пересчёт цен, проверка и списание остатков с блокировкой строк, снимок позиций, очистка корзины; идемпотентность по ключу (D-016).
- Мок-провайдер оплаты: модуль `payments` с интерфейсом под будущую ЮKassa; страница оплаты с успехом / отказом; вебхук-подобный эндпоинт меняет `payment_status` и статус заказа (D-043); при отказе, отмене или истечении 5 минут остатки возвращаются.
- Кабинет по account.html: профиль, адреса, история заказов с фильтром (все / активные / завершённые), шкала статуса, страница заказа.
- «Повторить заказ»: `POST /orders/:id/repeat` добавляет доступные позиции в корзину по текущим ценам и возвращает список недоступных, UI показывает его (D-041).

**Критерии готовности**
- Тесты: нельзя заказать больше остатка; цена с клиента игнорируется; гонка двух заказов за последний флакон; возврат остатков при отмене; повтор заказа с частично недоступными позициями; переходы статусов.
- e2e: каталог → корзина → оформление → оплата → заказ в кабинете — для пользователя и для гостя.

**Критерии готовности**
- Тесты: права доступа ко всем admin-эндпоинтам, недопустимые переходы статусов, уведомления при пополнении остатка.

## Этап 9. Анимации и полировка ✅

**Критерии готовности**
- Нет просадок FPS на среднем телефоне (Performance), CLS не растёт.
- С reduced motion всё доступно и читаемо.

## Этап 9.1. Выразительная анимация ✅

**Цель:** движение, которое делает витрину «дорогой»: маски, медленный параллакс, инерция и две фирменные сцены — в стиле «сдержанно-дорого».

**Задачи**

**Критерии готовности**
- 95-й перцентиль кадра ≤ 20 мс, долгих кадров не больше 2, CLS ≤ 0,01 (CPU ×4, 390 и 1440 px).
- При reduced motion ничего из этого нет и GSAP не грузится; axe — 0 нарушений; основной бандл растёт не больше чем на 5 КБ.

## Этап 10. QA и публикация ⬜

**Цель:** магазин опубликован и проверен.

**Задачи**
- Playwright e2e в Chromium и WebKit: каталог → товар → корзина → вход → оформление → мок-оплата → заказ в кабинете; гость → вход → слияние корзины; админ меняет статус заказа; axe в e2e.
- Lighthouse (mobile) для главной, каталога и товара: Performance ≥ 90, Accessibility ≥ 95, Best Practices ≥ 95, SEO ≥ 90; исправить найденное.
- Кросс-браузер: Safari 14.1 / iOS 14.5 на реальном устройстве или в облачной ферме.
- Проверка безопасности: заголовки, CSRF, rate limit, права, `pnpm audit`.

- «Срез» закрепляется по центру экрана: слои пирамиды раскрываются по одному, шкала времени загорается следом. «Как рождается аромат» закрепляется: линия идёт от этапа к этапу, этапы проявляются, точки «загораются».
- Карточки: каскад (снимок из-под маски, текст следом) в «Образцах породы», каталоге, избранном и «Из той же породы»; на десктопе — тёплое пятно света за курсором и медленное приближение снимка.
- Полёт флакона со страницы товара в значок корзины по дуге.
- Заставка при первом входе на главную: «НИША» на срезе из четырёх слоёв, слои расходятся за 1,2 с, первый экран появляется под ними.
- Найдено и исправлено по ходу: SplitText по умолчанию превращал неразрывные пробелы в обычные; `aria-label` на абзаце (axe); приглушённые метки шкалы давали низкий контраст до начала сцены; на десктопе подвал был виден под скелетоном товара, и страница выталкивала его вниз (CLS 0,24, было и до этапа).

**Проверено**
- Тесты: web 140 (инерция: шаг сглаживания и пиксели колеса; интерполяция глубины), api 153, contracts 15.
- e2e — 55 сценариев (+11), все зелёные: при reduced motion нет GSAP и SplitText, нет шторки, якорь и «назад» работают; после прокрутки ни одна строка и ни один снимок не остались под маской; закреплённые сцены отпускают страницу, подвал достижим; «Мастерская» из меню доводит до секции; шторка уходит с новой страницы; заголовки под маской читаются целиком.
- Производительность (production-сборка, Chromium, CPU ×4, прокрутка главной, товара и каталога; телефон 390 px и десктоп 1440 px колесом с инерцией): 59–60 fps, 95-й перцентиль кадра 16,7–16,8 мс, долгих кадров нет, CLS ≤ 0,0001.
- axe — 0 нарушений на главной, каталоге, товаре, журнале и статье (1440 и 360 px), горизонтальной прокрутки нет. ES-Check — все чанки ES2020.
- Видео прокрутки главной и товара (десктоп и телефон) — показано перед слиянием.

**Отложено / известные проблемы**
- Основной бандл: 643,0 КБ + общий чанк `jsx-runtime` 8,8 КБ (его Rollup вынес из основного, когда появились ленивые сцены), итого +8,8 КБ к этапу 9 (gzip +3,9 КБ). Цель «не больше +5 КБ» выполнена по gzip, по несжатому размеру — нет. Десктопные сцены уже вынесены отдельными чанками; дальше — разделение по маршрутам на этапе 10.
- Горизонтальный проезд «Как рождается аромат» заменён закреплённым поочерёдным раскрытием: по макету пять этапов и так стоят в ряд, ехать им некуда.
- Приближения снимка в «Срезе» нет: в этой секции нет снимка флакона (только пирамида).
- Полёт в корзину — только со страницы товара: после выбора объёма в карточке подтверждение показывает сама шторка, а значок корзины закрыт затемнением.
- «Слои с разной скоростью» (`data-speed` у разделителей) не сделаны вместе с отказом от ScrollSmoother: слои разделителей тоньше 8 px, сдвиг между ними читался как дрожание.
- Проверка на настоящем Safari 14 / iOS 14.5 — этап 10.

**Правки после показа — 2026-11-11**
- «Каменная шторка» между страницами убрана: задерживала каждый переход. Заставка остаётся — один раз за визит при входе на главную.
- «Срез» и «Как рождается аромат» держат прокрутку один раз: после прохода закрепление снимается без скачка, при прокрутке вверх и повторном проходе секции не останавливают страницу; при возврате на главную в том же визите сцены сразу в конечном виде.
- Проверено: e2e — 55 сценариев зелёные (новый: после прохода закреплений на странице не остаётся), lint, typecheck, тесты web 140 / api 153 / contracts 15, ES-Check. В одном общем прогоне `pnpm test` упал один тест api (под нагрузкой, параллельно с web); в четырёх следующих прогонах — зелёный, не воспроизводится. Следить в CI.
- Основной бандл после удаления шторки — 651,8 КБ одним чанком (общий `jsx-runtime` снова внутри), то есть те же +8,8 КБ к этапу 9.
