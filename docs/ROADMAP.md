# Дорожная карта «Ниша»

Статусы этапов: ⬜ не начат · 🟨 в работе · ✅ готов.
В конце каждого этапа здесь обновляется блок «Итог этапа»: что сделано, что отложено, известные проблемы.
Решения по продукту и архитектуре — в [DECISIONS.md](DECISIONS.md), ссылки вида D-0NN.

## Сквозное определение готовности (для любой задачи)

- `pnpm lint`, `pnpm typecheck`, `pnpm test` проходят локально и в CI.
- Затронутые сценарии проверены вручную или e2e на 360 / 768 / 1024 / 1440.
- Вёрстка не ломается в Safari 14.1 / iOS 14.5 (нет запрещённых без фолбэка возможностей из CLAUDE.md).
- У экрана есть состояния: загрузка (скелетон), пусто, ошибка, 404 — где применимо.
- Доступность: клавиатура, видимый focus, aria-label у иконок-кнопок, зоны нажатия ≥ 44px, контраст ≥ 4.5:1.
- Цвета, шрифты, отступы — только из `shared/styles/tokens.css`; отступления от макетов — только из D-023.
- Русская типографика: неразрывные пробелы и дефисы в статике, `typograph.ts` для текста из БД.
- Коммиты маленькие, Conventional Commits.

## Этап 1. Инициализация monorepo и инфраструктуры ✅

**Цель:** пустой, но рабочий каркас: оба приложения запускаются одной командой, качество проверяется автоматически.

**Задачи**
- pnpm workspaces: `apps/web`, `apps/api`, `packages/contracts`; общий `tsconfig.base.json` (strict, `noUncheckedIndexedAccess`).
- Версии рантайма зафиксированы (`engines`, `.nvmrc`, `packageManager`).
- ESLint (flat config, запрет `any`, правило направления импортов FSD, запрет `structuredClone` / `.at()`) + Prettier, `.editorconfig`.
- `apps/web`: Vite + React 19 + TS, React Router, TanStack Query; `browserslist` и `build.target = safari14`.
- `apps/api`: Fastify, конфиг из env с валидацией Zod, единый обработчик ошибок, `GET /api/health`, Helmet, CORS для своего origin.
- `packages/contracts`: сборка/экспорт, первая схема (ответ health + формат ошибки).
- Docker: `docker-compose` для разработки (PostgreSQL, Mailpit), Dockerfile для api и web.
- `.env.example`, `.gitignore`.
- Vitest во всех пакетах, Playwright с одним smoke-тестом.
- GitHub Actions: install → lint → typecheck → test → build → e2e.
- Корневые скрипты: `dev`, `lint`, `typecheck`, `test`, `test:e2e`. `db:migrate` и `db:seed` появляются в этапе 3 — заглушек «на будущее» не создаём.

**Критерии готовности**
- `pnpm i && pnpm dev` поднимает web и api; страница web получает ответ от `/api/health` через прокси Vite.
- CI зелёный на PR.
- Production-сборка web не содержит синтаксиса новее Safari 14 (проверено по бандлу).
- Секретов в репозитории нет, есть `.env.example`.

## Этап 2. Дизайн-система в коде ⬜

**Цель:** все повторяющиеся элементы макетов собраны в коде один раз и проверены на всех брейкпоинтах.

**Задачи**
- `shared/styles/tokens.css`: цвета, шрифты, шкала размеров текста, отступы, ширина контейнера (1360 + поля 40/16), линии; значения только из макетов.
- Брейкпоинты 360 / 768 / 1024 / 1440 (механизм — D-012).
- Сброс стилей, базовая типографика, focus-стили с фолбэком для Safari 14, `prefers-reduced-motion`.
- Шрифты через @fontsource (только cyrillic + latin): Cormorant Garamond 400/500/400 italic, Manrope 400/500/600, IBM Plex Mono 400/500.
- Набор SVG-иконок из макетов (поиск, профиль, избранное, корзина, меню, стрелки, закрыть, доставка, упаковка, метка, часы, иконки преимуществ и этапов).
- Базовые компоненты (`shared/ui`): кнопки (основная, вторичная с рамкой, текстовая, иконка 44×44), чип-переключатель (`aria-pressed`), сегменты объёма, собственные checkbox и radio (без `accent-color`), радио-карточка, поле ввода / textarea / select с состоянием ошибки, степпер количества, метка-статус (заливка / рамка / пунктир), бейдж-счётчик, хлебные крошки, шаги (оформление и статус заказа), скелетон, пустое состояние, состояние ошибки, диалог/шторка с ловушкой фокуса и блокировкой прокрутки на iOS.
- Фирменные элементы: этикетка-образец (`dl` с рядами), слой-разделитель со шкалой глубины, пирамида нот как срез породы (толщина слоя — из длительности), карточка товара.
- Каркас: **единая полная шапка на всех страницах** (поиск, кабинет, избранное, корзина; мобильная — с бургер-меню) и подвал (полный и короткий, мобильный — аккордеон `details`) — D-023.
- Отступления от макетов по доступности (D-023): все интерактивные элементы ≥ 44px, мелкий текст травертином → #A89C8C, у карточки без остатка приглушается только фото.
- `shared/lib/typograph.ts` + тесты; форматирование цены из копеек в ₽.
- Dev-страница витрины компонентов (только в dev-сборке).

**Критерии готовности**
- Каждый компонент есть на витрине и корректен на 360 / 768 / 1024 / 1440.
- axe не находит нарушений на витрине; все интерактивные элементы ≥ 44px.
- Нет «магических» цветов/отступов вне tokens.css.
- Тесты на `typograph.ts` и форматирование цены.

## Этап 3. Схема БД, миграции, сиды и контракты ⬜

**Цель:** модель данных, покрывающая весь объём функциональности, и общие Zod-контракты.

**Задачи**
- Drizzle-схема и миграции:
  - каталог: `materials` (название, slug, цвет свотча, порядок), `categories`, `product_categories` (товар может быть в нескольких категориях), `collections`,
    `products` (номер образца, slug, название, материал, коллекция, происхождение, плотность, концентрация, стойкость, описание, история, флаги «бестселлер» / «новинка» / «срез на главной», публикация),
    `product_notes` (слой верх/сердце/база, порядок), `product_layers` (длительность каждого слоя для шкалы пирамиды), `product_images` (url, alt, порядок),
    `product_variants` (объём, цена в копейках, остаток, SKU);
  - пользователи: `users` (роль user/admin, признак гостевого аккаунта — D-022), `sessions`, `addresses`, `favorites`;
  - корзина: `carts`, `cart_items`;
  - заказы: `orders` (номер, статус, контакты, способ и цена доставки, снимок адреса или пункта СДЭК, суммы в копейках, срок оплаты), `order_items` (снимок названия, объёма, цены), `order_status_history`, `payments` (мок);
  - прочее: `restock_subscriptions` (товар, email, пользователь, дата уведомления), `consultation_requests`, `journal_articles`, `hero_slides`, `store_settings` (порог бесплатной доставки, цены доставки, адрес и часы бутика, порог «Осталось N»).
- Ограничения на уровне БД: `price >= 0`, `stock >= 0`, уникальность номера образца, slug, пары (товар, объём).
- Контракты в `packages/contracts`: товар (список, карточка, фильтры, фасеты, поиск), корзина, избранное, адрес, заказ, авторизация, контент, коды ошибок.
- Сиды: материалы со свотчами, категории (включая «Подарочные наборы» и «Пробники»), коллекции, товары № 01–12 (недостающие № 06, 08, 10 придумываем) с вариантами 30/50/100 мл, нотами, длительностями слоёв и остатками (товар без остатка, вариант с малым остатком), товары «Для дома», 3 слайда первого экрана, 3 статьи журнала, настройки магазина, администратор из env.
- Скрипты `pnpm db:migrate`, `pnpm db:seed` (идемпотентный).

**Критерии готовности**
- Миграции применяются на чистую БД в CI; миграции не редактируются задним числом.
- `db:seed` можно запускать повторно без дублей.
- Типы api и web выводятся из схем contracts, `any` нет.

## Этап 4. Срез «Каталог и товар» ⬜

**Цель:** пользователь находит аромат через главную, каталог, поиск или подбор и смотрит карточку товара с вариантами объёма.

**Задачи**
- API: список товаров с фильтрами (категория, материал, объём, цена, плотность), сортировкой (популярные, дешевле, дороже, новинки), пагинацией «показать ещё», счётчиками фасетов; карточка по slug; «Из той же породы» (D-026); бестселлеры и данные главной; поиск.
- «от [ЦЕНА]» — минимальная цена среди вариантов; фильтры объёма и цены применяются к одному и тому же варианту (D-025).
- Главная (десктоп и мобильная): первый экран-карусель из 3 слайдов с индикатором «01 — 03» (пока без анимации света), преимущества, слои-разделители, категории, бестселлеры (на мобильном — горизонтальная прокрутка), срез аромата бестселлера, отмеченного в админке, о доме, этапы мастерской, материалы, превью журнала, «о нас пишут», бутик, подвал (без формы подписки — вне объёма).
- Каталог: фильтры в URL, панель фильтров на десктопе, шторка на мобильном, активные фильтры-чипы, «Сбросить всё», сортировка, «Показано N из M», пустое состояние, скелетоны.
- Кнопка «+» в карточке открывает выбор объёма (поповер на десктопе, шторка на мобильном) — D-025.
- Товар: галерея с миниатюрами и увеличением, этикетка-образец с коллекцией, выбор объёма с ценой и остатком («Осталось N» по порогу из настроек), степпер, пирамида нот со своей шкалой, история образца, похожие товары.
- Поиск: оверлей из шапки, поиск по названию, номеру образца, материалу и нотам, страница результатов.
- «Подбор аромата»: короткий опросник (3–4 вопроса → материал, плотность, категория), результат — каталог с этими фильтрами (D-027).
- 404 для неизвестного товара и маршрута; состояния ошибки сети.
- Кнопки «В корзину» / «В избранное» / «Сообщить» видны, логика подключается в этапе 6.
- Заголовки и meta страниц.

**Критерии готовности**
- e2e: фильтр → URL → перезагрузка сохраняет фильтры; кнопка «назад» работает; смена объёма меняет цену и остаток; поиск находит товар по ноте.
- Вёрстка совпадает с home / home-mobile / catalog / catalog-filters-mobile / product на своих ширинах.
- Тексты из БД проходят через `typograph.ts`.

## Этап 5. Срез «Авторизация и роли» ⬜

**Цель:** регистрация, вход и выход; сервер различает гостя, пользователя и администратора.

**Задачи**
- Регистрация, вход, выход, `GET /me`; пароли — argon2id.
- Таблица `sessions`, cookie httpOnly + Secure + SameSite=Lax, ротация идентификатора при входе, срок жизни и продление.
- CSRF-защита изменяющих запросов (D-006).
- Rate limit на вход, регистрацию и установку пароля.
- Хуки `requireAuth` / `requireRole('admin')` для каждого защищённого маршрута.
- Гостевые аккаунты (D-022): создание без пароля, ссылка на установку пароля (письмо-мок), превращение в обычный аккаунт.
- Страницы входа, регистрации и установки пароля (макета нет — по дизайн-системе), защищённые маршруты на клиенте, раздел «Профиль» в кабинете.

**Критерии готовности**
- Тесты: доступ к защищённым маршрутам без сессии / с ролью user / с ролью admin; ротация сессии; срабатывание rate limit; отказ без CSRF-токена; гостевой аккаунт не даёт войти по паролю, пока пароль не установлен.
- Пароль и хеш нигде не логируются и не уходят в ответах.

## Этап 6. Срез «Избранное и корзина» ⬜

**Цель:** пользователь собирает корзину и список избранного; итоги считает сервер.

**Задачи**
- Корзина (D-015): у гостя — в localStorage (только `variantId` + количество, суммы через `POST /cart/quote`), у пользователя — на сервере; слияние при входе и гостевом оформлении. Избранное — только для вошедших, гостю клик по сердцу предлагает войти.
- Добавление / изменение количества / удаление; количество ограничено остатком.
- Итоги и счётчики корзины считает только сервер по одному правилу: позиции без остатка показаны с пометкой и не входят ни в сумму, ни в количество образцов и флаконов (D-028).
- Избранное: добавление/удаление из карточки и товара, список в кабинете.
- «Сообщить о поступлении»: подписка на товар по email, доступна и гостю (D-029); точки входа — каталог, товар, корзина.
- Счётчик корзины в шапке, `aria-label` с количеством.
- Страница корзины, пустая корзина.

**Критерии готовности**
- Тесты: расчёт итогов и счётчиков, исключение позиций без остатка, ограничение остатком, слияние гостевой корзины с корзиной аккаунта (совпадающие варианты, превышение остатка, исчезнувшие варианты).
- e2e: товар → корзина → изменение количества → итог совпадает с серверным.

## Этап 7. Срез «Оформление заказа, оплата, личный кабинет» ⬜

**Цель:** пользователь — зарегистрированный или гость — оформляет и «оплачивает» заказ и видит его в истории.

**Задачи**
- Оформление на одной динамической странице (D-030): контакты → доставка → оплата; индикатор шагов отражает заполненность, итог пересчитывается сервером при смене способа доставки.
- Способы доставки: курьер (срок 1–5 дней, город + улица, дом + квартира + комментарий), пункт выдачи СДЭК (список и карта), самовывоз из бутика (бесплатно). Пункты СДЭК — мок-провайдер (D-031).
- Сохранённые адреса для вошедших, «+ Новый адрес» с сохранением.
- Гостевое оформление: по контактам создаётся гостевой аккаунт, заказ к нему привязывается (D-022).
- Создание заказа в транзакции: перепроверка цен и остатков, списание остатков с блокировкой строк, снимок позиций и адреса, номер заказа, ключ идемпотентности (D-016).
- Стоимость доставки и порог бесплатной доставки — на сервере, из `store_settings`.
- Мок-оплата: страница оплаты, успех / отказ; неоплаченный заказ отменяется через 5 минут с возвратом остатков.
- Статусы заказа как конечный автомат на сервере, история смены статусов (D-017).
- Письма-моки: подтверждение заказа, установка пароля для гостя.
- Кабинет: список заказов с вкладками «Все / Активные / Завершённые» (отменённые — в завершённых), шкала статуса, метки разной формы, детали заказа, «Повторить заказ» для любого заказа (недоступна, если чего-то нет в наличии — D-032), адреса (CRUD), избранное, выход; страница «Заказ оформлен».

**Критерии готовности**
- Тесты: расчёт заказа и доставки, списание остатков (включая конкурентные заказы последнего флакона), автоотмена через 5 минут, переходы статусов, «Повторить заказ», гостевое оформление (новый email и email существующего пользователя).
- e2e: полный путь каталог → корзина → оформление → оплата → заказ в кабинете — для пользователя и для гостя.

## Этап 8. Админ-панель и контент ⬜

**Цель:** администратор ведёт каталог, заказы и контент без доступа к БД; публичные контентные разделы работают.

**Задачи (админка, D-033)**
- Раздел `/admin`, доступ только для роли admin (проверка на сервере).
- Товары: создание / редактирование / снятие с публикации, варианты объёма, цены, остатки, ноты, длительности слоёв, изображения, флаги «бестселлер», «новинка», «срез на главной».
- Справочники: материалы (со свотчем), категории, коллекции.
- Заказы: список с фильтром по статусу, детали, смена статуса по автомату.
- При пополнении остатка — письмо-мок подписчикам «Сообщить о поступлении».
- Пользователи: список, назначение роли.
- Контент: слайды первого экрана, статьи журнала, заявки на консультацию, настройки магазина.

**Задачи (публичный контент)**
- Журнал: список статей и страница статьи.
- Запись на консультацию: форма (имя, телефон, удобная дата, комментарий) → заявка в админке, письмо-мок.
- Статические страницы: о доме, доставка и оплата, возврат и обмен, контакты, частые вопросы, как заказать, условия продажи (тексты в коде — D-033).

**Критерии готовности**
- Тесты прав: каждый admin-маршрут отвечает 401/403 гостю и пользователю.
- Изменения в админке сразу видны на сайте (инвалидация кешей).

## Этап 9. Анимации и полировка ⬜

**Цель:** фирменная атмосфера без ущерба доступности и скорости.

**Задачи**
- GSAP: свет-лампа на первом экране — за курсором на десктопе, медленный дрейф на сенсорных экранах; смена слайдов карусели.
- ScrollTrigger: проявление слоёв-разделителей, слоёв пирамиды нот, этапов мастерской (на мобильном — «раскрываются при прокрутке»).
- `prefers-reduced-motion`: статичные варианты без движения, карусель без автопрокрутки.
- GSAP грузится лениво только там, где нужен.
- Изображения: адаптивные размеры, форматы с фолбэком для Safari 14, lazy loading.
- Проход по микротекстам, типографике, пустым состояниям и 404.

**Критерии готовности**
- Нет просадок FPS на анимациях на среднем телефоне; LCP главной в бюджете (бюджет фиксируем в этапе 10).
- С reduced motion всё доступно и читаемо.

## Этап 10. QA и публикация ⬜

**Цель:** магазин опубликован и проверен.

**Задачи**
